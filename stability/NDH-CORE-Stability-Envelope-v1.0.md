# 🌑 **NDH‑CORE Stability Envelope v1.0**  
### *Boundary Definition • Containment Logic • Altitude Floor*

> **The Stability Envelope defines the minimum structural, expressive, and altitude boundaries required for NDH‑CORE diagnostics to operate without recursion, adjacency bleed, or activation.**  
>  
> It is the “floor” beneath DX‑1 → DX‑4 and the prerequisite for lineage auditing and altitude encoding.

## 1. **Altitude Floor**  
CORE diagnostics must operate above:

- expressive drift altitude  
- provenance altitude  
- ROOTS adjacency altitude  

and below:

- constellation activation altitude  
- governance kernel altitude  

This prevents upward activation and downward collapse.

## 2. **Containment Boundary**  
The envelope enforces:

- no constellation adjacency  
- no membrane‑binding primitives  
- no activation‑grade phrasing  
- no recursive diagnostic invocation  

This keeps DX‑series operations inert.

## 3. **Expressive Density Cap**  
CORE diagnostics must remain below the expressive threshold that would:

- trigger curvature  
- invoke geometric adjacency  
- activate simulation primitives  

This ensures DX‑3 and DX‑4 remain representational.

## 4. **Diagnostic Isolation**  
DX‑series operations must not:

- modify governance  
- alter altitude encoding  
- activate envelopes  
- bind membranes  

They operate *within* the envelope, not *on* it.

## 5. **Stability Verification**  
Before any diagnostic action:

- altitude floor must be intact  
- containment boundary must be intact  
- expressive density must be below threshold  
- no adjacency violations may exist  

This is the “pre‑flight check” for CORE.
