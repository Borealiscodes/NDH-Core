## **4. CORE‑Level Naming Requirements**

### **4.1 Maintain Acronym Shape‑Families**  
Operators must belong to predictable naming clusters (e.g., RTO, NDIE).

### **4.2 Avoid Divergent Naming**  
Single outlier acronyms cause pattern‑collapse for dyslexic developers.

### **4.3 Preserve Operator Rhythm**  
NDH‑CORE naming must follow consistent syllable patterns.

### **4.4 Enforce Provenance‑Safe Naming Rules**  
Naming must reflect operator lineage and non‑dual boundaries.

### **4.5 Document Naming Invariants in CORE Governance**  
Naming rules must be part of NDH‑CORE’s architectural documentation.
